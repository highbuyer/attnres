对于 135M 模型，完整的自我批评（Constitutional AI 那种生成→批评→修改循环）做不了——模型太小，没有足够的能力评估自己的输出。

  但有几种实际可行的方式：

  1. 训练数据注入（最简单，推荐）

  在 SFT 数据里加入"承认不知道"的样本：

  {"messages": [
    {"role": "user", "content": "量子色动力学的渐近自由是怎么证明的？"},
    {"role": "assistant", "content": "这个问题超出了我的能力范围，我无法给出准确回答。建议查阅专业教材。"}
  ]}

  批量构造这类数据：用大模型判断 Belle 数据中哪些 assistant 回答是在胡编，然后替换成拒绝回答。

  2. 拒绝采样（Rejection Sampling）

  1. 用当前 SFT 模型对同一个问题生成 5~10 个回答
  2. 用大模型（Claude/GPT）打分，选最好的
  3. 用最好的回答重新训练

  成本：需要调用大模型 API 打分。

  3. DPO（最有效但复杂）

  1. 用 SFT 模型生成两个回答
  2. 人工或大模型标注哪个好（chosen/rejected）
  3. 用 DPO loss 训练偏好

  loss = -log σ(β * (log π(chosen) - log π_ref(chosen) - log π(rejected) + log π_ref(rejected)))

  建议

  先做方式 1，成本最低：构造 1000~2000 条"拒绝回答"的样本混入 SFT 数据。你有 Claude API 吗？可以批量让 Claude 判断哪些 Belle 回答在胡编，自动生成拒绝数据。
